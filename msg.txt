Refuse a missing parser, and compare line coverage as half-open ranges

Both found in review.

parser_fingerprint() imported markdown_it before calling _parser(), so a missing
dependency raised ImportError instead of the MarkdownParserError that carries
install guidance. That escaped analyze_text() and the CLI's error handling and
contradicted the contract that an unusable parser is refused rather than
crashing. _parser() now runs first and is the only gate; once it returns the
import cannot fail. Pinned by a test that blanks the module in sys.modules,
which raises ModuleNotFoundError on the previous ordering.

_uncovered() compared blocks and lines as though their ends were inclusive: it
advanced past blocks ending before a line rather than at it, and accepted a
block starting at a line's end as covering it. Both ranges are half-open, so a
block that stops exactly where a line begins shares no character with it and
must not count as covering it -- an undercount in the one number that exists to
report lines nothing claimed.

This is a latent defect rather than a live one, and the tests say which is
which. Every extent reaching _uncovered() today is built by _mapped_span() from
bounds[first][0] and bounds[last][1], so it starts at a line's first character
and ends at a line's last, and a terminator always separates one block's end
from the next line's start. Searching 1884 generated documents found no input
where the old and new arithmetic disagree. The interval fix is therefore pinned
by direct tests on _uncovered(), which fail on the previous comparisons, and the
caller invariant that makes it unreachable is pinned separately -- so if extents
ever grow to include their terminator, the sweep is already correct and the
invariant test says what changed.
